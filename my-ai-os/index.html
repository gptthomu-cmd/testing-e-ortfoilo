02 Design rules

How the system is allowed to behave

An intelligence layer that touches business records and personal data needs rules before it needs features.

Rule 01

Local first

Sensitive data is processed on owned hardware wherever it is practical to do so. Hosted models are used deliberately, not by default.

Rule 02

Model-agnostic

No single provider gets to be the system. Routing means the best available model for a task — and the ability to swap it out.

Rule 03

Scoped authority

Agents get specific tools and explicit limits. An agent that can act is an agent with boundaries, or it is a liability.

Rule 04

Memory with consent

Memory is what makes an assistant useful and what makes it dangerous. It is stored deliberately, inspectable, and deletable.

Rule 05

Deterministic where possible

If a script can do it reliably, a model should not be guessing at it. Intelligence is spent where it changes the outcome.

Rule 06

Everything closes the loop

Outputs return to the data layer as records — so the system gets more useful the longer it runs instead of starting over each time.

Where it sits in the ecosystem

My_AI_OS is the intelligence layer. It is designed to sit underneath everything else: business operations at NKT Group, the charging data and reporting at NKT Charge Hub, and eventually the financial system in Apex Creator OS.

In practice that means one stack of knowledge and memory serving several very different questions — operational, financial and technical — instead of five separate tools that each know a fifth of the picture.

What stays private

No personal data, business record, credential, API key or model output from private systems is published on this website. The architecture is public; the data inside it is not, and never will be.
