How the lab works

THOMU LAB is an active workbench, not a portfolio. Some experiments become products; most exist to answer a question and are then retired, documented or folded into something else.

  1. Question. Something needs to be understood — a cost, a bottleneck, a capability.
  2. Prototype. The smallest version that can answer it, built with whatever is fastest: an AI-assisted script, a container, a printed part.
  3. Test against reality. If it touches a business, it has to survive actual use.
  4. Adopt, publish or retire. The only three honest outcomes.

The two largest things to come out of this process so far are My_AI_OS — the intelligence layer — and Apex Creator OS — the financial operating system concept. Both are described with their real status, not their ambition.

Building principles

  • Modular — replaceable parts, no single point of failure.
  • Private — data stays owned and controlled.
  • Automated — if it repeats, it should run itself.
  • Self-hosted where practical — ownership beats convenience.
  • AI-assisted — intelligence as leverage, not as a crutch.
  • Open-source friendly — standing on software that can be inspected.
  • Long-term maintainable — built to be understood in five years.

Lab status
